### 1-1. 원문이 가리키는 A · B · C (Claude가 제안한 것, 사용자 원문 아님)

- **A(시제품):** 신규 브랜드 상담 → 제안서 초안. 브랜드 담당자가 원하는 제품을 적으면 AI가 빠진 정보를 되묻고, 기본 처방 후보 · 예상 일정 · 판매 국가별 확인 항목을 정리한다. 영업 담당이 고쳐 확정하면 제안서 초안이 나온다.
- **B(제안만):** 신규 브랜드 발굴 목록. 판단: 남의 사이트 자료를 긁어 오면 약관 · 개인정보 문제가 생길 수 있다.
- **C(제안만):** 기존 고객 재주문 알림. 판단: ERP 데이터가 있어야 해서 가상 데이터로는 설득력이 약하다.
- 묶는 흐름: B 발굴 → A 상담 · 제안 → C 재주문(유지).

### 3-2. 시연 뒤 추가 인터뷰 (2026-11-24)

Q13: '문의' 칸은 언제 차나? (사용자 원문: "그럼 문의상자는 언제 차나요?")
A13: 지금은 제출 즉시 '검토'로 넘어가 '문의'가 늘 0이다. '문의' = 영업이 아직 열어 보지 않은 새 문의로 바꾼다. 영업이 처음 열 때 '검토'로 간다. 사용자 이해(원문): "문의는 ai가 넘기는 칸이라서 아무도 안 볼 확률이 없고 검토만 아무도 안 볼 확률이 있는게 되겠네요?" → 바꾸면 '문의'에 쌓인 수가 곧 아무도 안 본 문의 수가 된다.

Q14: 가격은 보통 언제 넣나? (사용자 원문: "가격은 언제 넣나요? 보통")
A14: 두 번 넣는다. 제안 때 예상 단가(가견적, 범위 글), 샘플 확정 뒤 수주 때 확정 단가. 일반 흐름으로 정리한 것이며 공식 자료로는 확인 못 함(AS-8).

Q15: 샘플 요청은 아무 때나 누를 수 있나? (사용자 원문: "샘플 주세요 요청 버튼도 그냥 누르는 게 아니라 제한이 있거나 가격에 포함되지 않나요?")
A15: 조건을 둔다. 영업이 제안 때 무상 샘플 횟수와 샘플비 안내를 적는다. 브랜드는 제안서에서 '샘플 요청'을 누르고, 무상 횟수를 넘으면 샘플비 안내에 동의해야 요청이 남는다. 처리 전 요청이 있으면 다시 누를 수 없다. 횟수 · 금액 숫자는 정해 두지 않는다(회사마다 다름).

## 5. 수용 기준 (EARS)

- 한 행 = 요구 1개 = 시험 1개 후보.

- 분류: SFR 기능 · DAR 데이터 · PER 성능 · SECR 보안 · CONR 제약.
- 근거: `Qn` 인터뷰 답 · `R1` 추가 요구 · `O1` 관찰(회사 홈페이지 색) · `Dn` 문서 · `I` 추론 · `AS-n` 가정.
